
# Impossible Puzzle

## 問題

長さが違うのに、同じ!?
```php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $A = $_POST['A'] ?? '';
    $B = $_POST['B'] ?? '';

    // type check
    if (!is_string($A) || !is_string($B)) {
        die('Invalid input');
    }
    // check
    if (strlen($A) != strlen($B) && $A == $B){
        echo "<blockquote>Congratulations! Here is your flag:\n" . getenv('FLAG') . "</blockquote>";
    }
    else {
        echo "<blockquote>Try again!</blockquote>";
    }
}
```

## 概要

問題文やソースコード、ブラウザで表示した時の英文が示すように、長さが異なりかつ等しい２つの文字列`A,B`の入力を求められているようです。

同じなのに長さが異なる文字列なんて存在するのでしょうか？

## 方針

PHPの`==`比較演算子の性質に注目する。

## 解法

PHPの`==`比較演算子は、数値として解釈できる場合は自動的に数値に変換して緩く比較を行います。（この性質をLoose Comparisonというそうです。）

したがって、
```php
123 == "123"
```
は`true`になります。

今回の問題では、直前に
```php
    if (!is_string($A) || !is_string($B)) {
        die('Invalid input');
    }
```
として型のチェックも行っていることから、実質`===`と同等のチェックを行っているようにも見えます。

しかし、同じ文字列型であったとしても、両方とも数値とみなせるものであれば数値として比較されるので、問題の条件を満たすことは可能です。

具体的にはどのような文字列を与えればいいのでしょうか？

私はここで、過去問の「💯」を思い出しました。
```
A: 100   B: 0100
```
これで突破できます。

他にもいろいろなやり方がありますよね。
```
A: 100   B: +100
```
```
A: 100   B: 100.0
```
```
A: 0   B: -0
```
```
A: 1000   B: 1e3
```
```
A: 0   B: 0e3
```
```
A: 0e1   B: 0e22
```

## まとめ

今回の問題は、フラグが示すように、「PHPの緩い比較は予期しない動作を引き起こす」というお話でした。

これ、リアルの実装でもやらかしそうな事ではあるので、気をつけなければいけないと思いました。

特に今回の問題のように型が同じことが保証されている場合は油断しそうです。

特段の理由が無い限りは、`==`ではなく`===`を使うようにした方が良いかもしれませんね。
